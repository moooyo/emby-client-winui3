# Default player-owner isolation checks

Run `--output-dir <new-directory> --lifecycle-isolation` only against the verified synthetic fixture on port 18961. `Start-SyntheticFixture.ps1` copies the existing fixture build into a fresh artifacts directory before starting it, so the server does not lock build outputs. No real credentials or arbitrary server URL are accepted by this mode.

The probe uses the default product player owner. It never enables either shared-player or native-HTTP construction controls. Bound Opening cancellation and pre-bind invalid-container rejection are separate gates. Failure after source binding is a separate [network-retry gate](NETWORK-RETRY.md), using valid 180-second media and a real cold-range HTTP 503. An `IsolationPassed` result always records `PostBindLateFailureGateStatus=NotEvaluated` and cannot substitute for that separate result.

Current FFmpeg-backed source creation rejects the 4,096 invalid container bytes before native source binding. The former source-bound decoder-failure assertion therefore failed before recovery. That original failed report remains unchanged. New runs label this observation `BeforeNativeSourceBinding` and must not present it as a passed post-bind failure gate.

| Check | Count | Required evidence |
| --- | --- | --- |
| Actual native Opening cancellation | 3 | A warmed product owner's new source is bound, its actual state is Opening, and the open task is pending. Seven native handlers are captured before cancellation. The temporary observation handler is removed before cancellation, the element detaches, and no start report is sent for the canceled session. A missed observation window fails instrumentation. |
| Pre-bind invalid-container rejection | 3 | A one-shot wrapper redirects only the injected request to 4,096 deliberately invalid MP4 bytes and clears authentication headers. Each cycle must make an actual invalid-media request, publish a supported engine failure before native source binding, produce no Start for that session, detach, and subsequently recover. Missing or post-bind observations fail this pre-bind gate. |
| Replay after Opening cancellation | 3 recoveries | Invoke exactly seven captured native delegates: Opened, Ended, Failed, StateChanged, PositionChanged, SeekCompleted, and DurationChanged. The captured Failed delegate must reject the retired session before reading its null synthetic arguments. |
| Replay after pre-bind rejection | 3 recoveries | Invoke only the captured retired Session failure entry point. No native delegates exist at pre-bind rejection, so this is one injected entry point, never seven native callbacks. |
| Retired ID commands | 9 per recovery | Old engine pause/resume/seek/volume/stop and coordinator pause/resume/seek/stop commands must preserve the replacement's paused source, position, muted volume, and report ownership. The stale volume command keeps mute enabled. |
| Concurrent Opening-time disposal | 1 independent engine | Two DisposeAsync calls begin while the source is bound and Opening. Both must initially remain pending. The second completion synchronously observes the shared drain task complete and owner cleared; both calls finish, the open cancels, the element detaches, and no canceled-opening Start is sent. |

Both replay helpers refuse to invoke a live or non-retired session. Capture failures are recorded as instrumentation failures without throwing from the product's Failed event observer. The report records capture stage, expected entry-point count, completed replay count of one or seven, and completed old-ID command count. A fixed seven is no longer assigned to a pre-bind capture.

Before replay, actual pause is observed and completed API activity must remain unchanged for 200 ms. The replay window permits only successful periodic TimeUpdate progress belonging to the replacement session; a missing event name is not accepted. Engine and API start indexes are retained. The bounded Opening/pre-bind recoveries retain their existing 50 ms paused-drift limit. The independent post-bind network gate requires zero native drift and an unchanged engine position.

The synthetic fixture has no transcoder. UnsupportedFormat or NativePlaybackFailure can trigger the normal product fallback and end with NoCompatibleStream; the next explicit healthy request must still recover. Only those expected fallback diagnostics are allowed. Native release errors or unrelated diagnostics fail the run.

Reports use source-generated JSON and hashed playback/session identifiers. Actual failure stage, source-bound observation, per-cycle invalid-media traffic, report ordering, replay counts, final detachment, and network quiet are retained. Raw media URLs and credentials are omitted. Captured delegates are released after each recovery, and this process exits before a formal resource run.

Retired entry-point replay is deliberate fault injection, not evidence that Windows naturally delivered late callbacks. Neither isolation mode replaces the unchanged twenty-loop resource gate, covers every concurrency interleaving, certifies real Emby/HLS compatibility, or establishes pixels or audible output. Historical reports retain their original executable identity, assertions, and outcome.
