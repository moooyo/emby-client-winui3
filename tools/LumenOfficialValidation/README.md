# Owned Official Emby Acceptance Backend

This remote-only helper creates one disposable official Emby 4.9.5.0 backend from the image digest already pinned by the protocol CI lane. It imports that lane's reviewed Docker ownership, internal-network inspection, and byte-transparent loopback relay instead of altering the existing CI or fixture-server implementations.

Use it only after explicit authorization to configure a synthetic acceptance backend. Execute on `ssh test-env`, never on the local Windows host. Copy `backend.py`, `Ci/protocol_ci.py`, and `Ci/loopback_relay.py` together into a unique remote staging directory. Run `python3 backend.py create` there. The command exports only a safe receipt path and fixed readiness fields. It never prints passwords or access tokens.

If the remote host's normal registry route is unavailable, `import_official_image.py` can download that same pinned official index, its Linux amd64 manifest, configuration, and layers using request-scoped public DNS answers. Every connection retains normal certificate/hostname validation, every content descriptor is SHA-256 checked, and the host's DNS/Docker configuration remains unchanged. `repack_official_image.py` additionally verifies the configuration's uncompressed layer digests and creates a classic Docker archive for hosts without OCI-archive support. Its private import receipt binds the loaded tag to the original pinned configuration ID. Supply that receipt to `backend.py create --import-receipt <exact-private-receipt>`; an arbitrary tag or different image configuration is rejected.

The backend has no Docker port publication, host network, hardware device, production directory, or production account. Its only entry point is an owned `127.0.0.1:19096` relay on the remote host. An independently owned SSH tunnel can expose that entry point at a local loopback address for a Windows application. No firewall, security product, normal service, or pre-existing listener is changed.

Eight movies and one four-episode series across two seasons are generated from a synthetic moving H.264 test pattern. Both AAC stereo tracks contain actual generated English/French speech, and every main video has English/French external SRT subtitles. Debian speech-synthesis packages are downloaded and extracted only under the private run directory; no system package is installed. Synthetic NFO files provide genres, fictional cast, overviews, and a collection. One real 20-second local trailer is generated. Favorites, played state, and a synthetic resume report belong only to the ordinary test user.

Generated credentials are private mode-0600 JSON files inside a mode-0700 directory. Copy them only into ignored local artifacts. The application credential format is `ServerUrl`, `Username`, `Password`, `ServerId`, and `ExpectedServerVersion`; the SSH-tunnel wrapper may add `OwnershipReceiptPath`. Never print those files, pass a password/token in CLI arguments, or include them in a commit.

The safe `owned-backend.json` receipt records the exact container/network IDs and names, owner label, pinned image and resolved image ID, synthetic directories, server identity/version, remote relay PID/start ticks, and finite expiry. The tunnel owner should add its local bind address, PID, and port after checking them. `catalog.json` contains synthetic item identities only. `summary.json` distinguishes protocol fixture readiness from native UI/decoder acceptance.

On Windows, `Manage-LocalTunnel.ps1 -Action Start -RemoteWork <exact-owned-directory>` copies only this backend's private artifacts into the ignored artifact directory and starts a hidden SSH process with an explicit loopback bind. `-Action Inspect` reads process/listener metadata only; it does not send an API or media request. The start-time guard compares normalized UTC ticks and supports the `DateTime`/`DateTimeOffset` values produced by PowerShell's JSON parser. `-Action Stop` stops only the PID whose start time, absolute executable path, and executable SHA-256 still match that receipt.

Run `python3 backend.py status --work <exact-owned-directory>` remotely for ownership and public-identity checks. Run `python3 backend.py stop --work <exact-owned-directory>` to request cleanup. The retained relay also expires after eight hours by default. Cleanup uses the existing CI ownership checks and removes only the exact owned container, its exact labeled internal network, and the checked private directory. It does not prune Docker, delete the shared image, remove the independent SSH tunnel, or touch unrelated services. Stop the SSH tunnel separately by its recorded process identity.

`verify_api.py --work <exact-owned-directory>` runs exactly 21 named API/HTTP checks remotely and exports only fixed safe fields plus source hashes. It creates an independent nonadministrator user for favorites, played state, resume hiding, and configuration writes. Administrator metadata writes preserve and restore complete JSON, including unknown nested fields. Newly created mutation collections and the temporary user are deleted with identity checks and absence readback. The application's main test user's progress/preferences are not modified. `HideFromResume` is checked only after the item is present in a real `MediaTypes=Video` resume query; it must preserve played state and position.

Observed official 4.9.5.0 behavior: item details omit `CanEditItems` for both roles; ordinary-user full metadata POST is rejected with HTTP 403, while metadata refresh and collection creation are allowed. Resume queries without an explicit video media type can return no video results even with saved progress. These are server observations, not a substitute for application permission handling or UI acceptance. `new-ui-api-summary.json` explicitly reports synthetic playback events and does not claim native decoding.

Do not interpret this lane as evidence of licensed features, native video rendering, audible playback on Windows, intro detection, HDR, ASS/PGS rendering, or production-server behavior. Its metadata and media are intentionally fictional.
