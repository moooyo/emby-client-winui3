## Candidate 04 revised implementation scope

The 2026-10-13 scope review requires official Emby data for media-information
features. Audio waveforms and media-time bitrate curves are excluded because
the reviewed public API does not supply their sample data. No local decoding,
packet sampling, OCR, custom analysis service, or synthetic chart is planned
to replace missing server facts. These two features currently have no local
analysis implementation; the existing UI reports unavailable data.

Text subtitle timelines remain supported because officially delivered SRT/VTT
already contains the cue start/end timestamps. Reading and presenting those
timestamps consumes server data. Regular Windows integration, playback
presentation and local user preferences remain normal client responsibilities.

Application-closed push, native Dolby Vision output, and guaranteed event replay
are not promised. Only confirmed native/player interfaces and documented Emby
delivery should be used for HDR, audio and subtitle presentation. Missing renderer
capabilities retain their unavailable state or negotiated server fallback.
Synchronized offline media and complete cross-device custom playback overrides
are outside this follow-up; no custom synchronization model is added by default.

## Candidate 04 remaining native and product boundaries

- End-to-end HDR and native Dolby Vision output are not accepted. Disabling HDR
  metadata does not perform HDR-to-SDR tone mapping. The new decoder wiring is
  conditional preparation, not a wider server device-profile promise.
- Display refresh-rate switching still needs display-mode ownership and reliable
  restoration on stop, failure, movement and exit. A delivered stream's nominal
  FFmpeg frame rate does not establish stable presentation cadence.
- TrueHD/bitstream passthrough requires a new output path; the current engine
  emits PCM/float audio outside its AAC/MP3 compressed path.
- Complete ASS/SSA effects and external two-file VobSub rendering remain outside
  the current text presentation and external-subtitle interfaces.
- Audio waveforms and packet bitrate history are excluded from implementation.
  Emby scalar bitrate metadata remains visible; local media analysis, custom
  aggregation services and substitute throughput charts are not planned.
- Application-closed push remains deferred without a confirmed third-party
  Windows delivery contract; no custom push relay is planned. The reviewed event
  contract provides no complete replay or exactly-once guarantee. Online alerts
  and refresh after reconnect retain their documented boundaries.
- Burned-in subtitle styling and OCR-based text/timeline reconstruction are
  excluded. Independent subtitle delivery may be used when the server supplies it.
- Synchronized offline media and complete cross-device client playback overrides
  remain outside this follow-up, although official download/settings interfaces
  provide foundations for a separately scoped feature.
- Actual target-server subtitle inspection delivery must be checked; the client
  requests `IsPlayback=false`, but only accepts a response that really contains
  usable External text delivery.
- Windows notification cards, idle SMTC, JumpList COM behavior, startup toggles,
  HDR displays and updater process/shortcut handoff require Windows acceptance.
  No desktop or system-registration action is executed while writing this code.
