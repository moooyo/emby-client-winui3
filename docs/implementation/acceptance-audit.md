# Acceptance audit: P0-P3

Snapshot: 2026-09-09. This assesses the [implementation plan](../architecture/windows-client-plan.md), sections 6-9 and phases P0-P3, against current code and completed receipts. It distinguishes implementation, native lifecycle evidence, actual UI observations, and installed-release acceptance. P4 remains optional and outside scope.

The [current status](status.md) owns the latest normal application publication and CI checkpoint. A publication still in progress is not an accepted executable, and observations below remain attached to their named artifacts rather than an assumed later SHA.

Project/interface names in the plan are illustrative boundaries, not a checklist of required assemblies. The present `Api`, `Playback`, and Windows app modules preserve the important separation. A separate `ICredentialStore`, reporter project, DI container, Generic Host, VLC adapter, or extra Toolkit package is not required merely to reproduce an example name. Local verification was explicitly authorized during implementation; the earlier research-stage `test-env` restriction does not invalidate that evidence.

## Environment and publisher gates

- **Interactive facilities:** physical media keys are unsupported by the current input tool. The recorded timeline keys and four Queue/Diagnostics focus-return paths have passed finite checks. Sustained physical key holds, remaining keyboard/focus paths, minimize/restore, suspend/resume, 100/150/200% DPI moves, actual display sleep, and audio-device transitions still need suitable Windows sessions/devices. HDR/color and audible/multichannel/passthrough claims need appropriate output hardware and observations. Some checks may be completed on the available machine; absence of evidence alone is not proof that the environment is blocked.
- **Installation facilities and identity:** choose a publisher identity/certificate and an authorized clean Windows installation environment before signing, changing trust, installing, upgrading, or uninstalling MSIX. Neither `makeappx` success nor the self-contained developer folder proves package activation or native dependency discovery after installation.
- **Owner decisions:** select the repository license, complete concrete redistribution review, choose release channels and a tested Windows/server support matrix. The development publisher placeholder and collected third-party notices do not make these decisions. Store publication and protected signing credentials remain release-owner actions.

The earlier 0251D189 checkpoint retains its burned-SRT and window-restoration observations. C6E8E17B supplies the later shared-owner frame/track/version/queue/diagnostics/playing-close evidence, 313A94C3 supplies actual manual Retry, and the dedicated external-subtitle receipt supplies one opt-in native plain cue and cleanup. DBC6C326 adds the finite timeline-key results and retains its original dialog-focus defect; 77A90D2D supplies the corrected four-entry focus behavior. Existing successes and failures remain scoped to their exact artifacts. These results do not close all P0-P3 gates: clean installation, wider subtitles/hardware, accessibility, long-duration performance, licensing, and publisher decisions retain their actual limits.
