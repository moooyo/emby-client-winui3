A captured window includes a small nonclient border: a 1440 x 900 capture in earlier candidates was actually a 1437.33 x 898 XAML viewport. This explained the apparent 1440 navigation breakpoint discrepancy; no breakpoint was changed to compensate for a screenshot border.

Only the owned, stopped candidate's window-placement file was adjusted. Calibrated outer sizes are 2182 x 1362 physical pixels for a 1440 x 900 XAML viewport, and 982 x 1092 for 640 x 720. The prototype browser uses an additional 48-pixel simulated taskbar. Its CSS vh measurements can therefore differ slightly from the native client viewport.

Visual review checks hierarchy, geometry, typography, colors, card proportions, selected states, responsive behavior and interaction flows. Native text rasterization, Acrylic blur, shadows and composition timing are not claimed to be pixel-identical to Chromium CSS. The application displays actual server capabilities instead of copying decorative 4K/HDR/Atmos labels or invented waveform data.

## Defects repaired during implementation and review

- Replaced the old vertical composition with V2 pages and corrected Home actions, horizontal settings tabs and media-information presentation.
- Fixed ResourceDictionary alias replacement. Removing a shared value could remove a different local key and cause a resource-key conflict. Construction-time replacement now preserves other local entries; live states update stable per-control brushes.
- Initialized the Home focus overlay correctly so a new session does not start with an opaque black cover.
- Initialized Composition Translation before stopping page animations and repaired shelf/backdrop unload/reload lifetimes.
- Moved the selected Home thumbnail outline outside its clipped image surface.
- Made navigation selection position a layout value with a relative transition, preventing the indicator from remaining under Home after overflow or theme changes.
- Preserved navigation focus across responsive updates and acquired native content-island focus on explicit foreground navigation.
- Ordered search focus after Low-priority rendering, loading, template creation and layout. Removed manual character insertion so the native editor retains input-method behavior.
- Prevented local episode/card arrow handling from consuming global history shortcuts. Added bounded handling for the observed missing Ctrl key-press route without duplicate actions.
- Followed the cross-season playback recommendation on first episode-page entry while preserving user choices and history.
- Replaced the failing SRT preparation path with bounded Unicode-aware SRT/WebVTT handling. Corrected Off-state subtitle notices and named the offset buttons for accessibility.
- Replaced fixed narrow Settings thresholds with the prototype's text basis, gap and measured-control fitting behavior.
- Disabled spell checking for title search so proper names are not marked as spelling errors.
- Routed ordinary player keys through the window root so caption focus cannot bypass playback shortcuts.

Acceptance-only diagnostics require EMBY_CLIENT_DATA_ROOT. They record fixed phases, action names, dimensions, booleans, exception types and code locations, not entered text, passwords, tokens or arbitrary key values.

## Verification limits

The real fixture sample verifies a concrete H.264/AAC playback path and source metadata. It does not certify real-server transcoding, broad codec/hardware compatibility, HDR output, passthrough, speaker audibility, multiple public accounts or passwordless-user behavior. These must not be inferred from a selector, build or HTTP fixture response.

The timed Home carousel, all accent colors, reduced-motion/high-contrast modes, every intermediate responsive breakpoint, every keyboard combination, subtitle drag-and-drop, chapter hover, every error-recovery path and physical OS media surfaces were not exhaustively exercised. Source implementation and unobserved behavior are distinguished above.
