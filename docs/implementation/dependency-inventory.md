## Scope and evidence

License fields below reproduce package metadata; a linked repository's license must not replace a NuGet package's different license metadata.

It predates FFmpegInteropX and does not establish the new decoder's published payload. Windows App SDK imports copy some native payload through MSBuild targets rather than NuGet's `runtime` or `native` asset lists. Consequently, an assets entry containing only `build` does not by itself prove that its package is irrelevant to distribution.

The table describes the resolved product graph and its distribution sources. It does not claim that every optional API is called or that every managed assembly survives NativeAOT trimming. Managed dependencies may be incorporated into the executable rather than remain as separate DLLs. The final release payload must be compared with this inventory after any dependency, SDK, trimming, or packaging change.

## Notice files to include in distribution

The [third-party notice directory](../../licenses/third-party/SOURCES.md) contains the original runtime and static-asset notice collection plus historical FFmpeg NuGet notices, Apache wrapper texts, Microsoft.Windows.CsWinRT notices, and the selected FFmpeg 8.1.3 runtime notice/source record. The machine-readable manifest is the authoritative file/hash inventory. Local NuGet files were copied byte-for-byte. WinUIEx and the FFmpegInteropX wrappers did not embed standalone license files, so their exact nuspec repository commits supplied the original texts. The original C#/WinRT source commit comes from the SDK-bundled DLL's file metadata; the separately resolved Microsoft.Windows.CsWinRT package now also has its own retained provenance. The Windows SDK license URL returned an RTF document; its original bytes and final response URL are retained rather than converted into a new license text.

The app project copies the complete `licenses/third-party/` tree into the product output under the same relative path, including `SOURCES.md` and `manifest.json`. The packaging step preserves these files in its snapshot. `Publish-Aot.ps1` also generates a [CycloneDX SBOM](sbom.md). Do not copy `tools/EmbyClient.VlcProbe` licenses or binaries into the product, and do not add build/test-tool notices to imply those tools are distributed with it.

Upstream notice texts remain in separate versioned directories, even when their bytes are identical, to keep each package's provenance explicit. Preserve their original copyright statements, formatting, and third-party lists. This collection records supplied terms and attribution material; it does not choose a license for the repository's own code or make a legal conclusion about a planned distribution. Reconcile it with the exact release payload and upstream terms when versions or deployment mode change.

The notice bundle is not complete corresponding source. Establish the combined application's section 6 route: section 6(b) requires practical replacement by an interface-compatible modified library; an applicable alternative such as section 6(a) requires the relevant source/object materials for relinking. The supplier's `SOURCE_OFFER.txt` records source access and is not a three-year written offer. NativeAOT does not remove these requirements. Record the source download location and replacement/relinking instructions with the release, as detailed in [current runtime provenance](../../licenses/third-party/Devenvy-FFmpeg-8.1.3.0/README.md). This is not legal advice or a completed release-compliance declaration.
