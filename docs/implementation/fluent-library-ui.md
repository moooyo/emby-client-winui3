# Fluent library UI

The V7 source implements the approved browsing and playback design using native WinUI 3 navigation, controls, theme resources, keyboard focus, and scrolling. This document describes the source behavior as of 2026-09-15. Actual V7 native acceptance is paused; the earlier native receipts below describe earlier source identities. Design previews are not evidence of native rendering acceptance.

## Structure

| Surface | Behavior |
| --- | --- |
| Navigation | The native window TitleBar supplies pane-toggle and contextual Back buttons. Search, Home, Favorites, and server-provided libraries are NavigationView items. Search opens a content-area AutoSuggestBox. Queue and account menu stay at the bottom. |
| Connection and accounts | First launch without saved accounts shows a direct credential form. Saved accounts offer a primary Continue action with manual credentials in an Expander. Add/Switch opens a cancellable dialog and retains the active session until the new connection commits. Settings-load recovery offers retry or a temporary session. Sign-out and device-local removal use confirmation dialogs, with explicit partial-sign-out recovery. |
| Home | Library tiles, landscape continue-watching and next-up shelves, and recent poster shelves for each library. Shelves use native horizontal scrolling; a separate See all action opens the complete collection. |
| Library and search | Virtualized adaptive poster wall with title/year/date-added sorting, direction, and an explicit All/Unplayed/Played watch-status selector. Submitted queries open a dedicated Search destination; empty search pages do not query media. Scrolling near the end loads another page automatically. |
| Movie and episode details | A continuous backdrop spans detail content, navigation, and title bar. Movies use posters and episodes use landscape artwork with series/episode identity and parent/next routes. Play/resume, favorite, expandable overview, and cast precede Media information cards grouped as Video, Audio, and Subtitles. Watched-state and playback alternatives live in More. |
| Series details | Season selection and a default episode list with a card-view toggle, artwork, progress, and available metadata. The primary action identifies the episode to resume or play. Cast and crew are available here too, and empty seasons keep the season selector accessible. |
| Person details | An independent PersonDetailsView presents the server's portrait, expandable biography, and paginated account-visible works. Back navigation restores loaded works, biography expansion, scroll, and focus anchors. Missing metadata and separate biography/works errors remain explicit. |
| Player | A centered play/pause action and ten-second seek controls sit below the timeline. Episode neighbors are independent of the manual queue. Queue and settings have separate panel entry points and content, with one visible at a time. The viewing surface is dark; windowed playback uses the existing native title bar. |

Server administration, metadata editing, media deletion, and the external-player plugin controls in the references are outside this interface. Playback source, audio, and subtitle selection remain in the existing player.

## Visual rules

- Native Segoe typography: 32 DIP page titles, 28 DIP detail titles, 20 DIP shelf titles, 14 DIP card titles, and 12 DIP supporting metadata. Poster and landscape titles can occupy two lines.
- A 208 DIP expanded navigation pane and 48 DIP compact icon rail. NavigationView uses 640/1008 DIP compact/expanded thresholds; wide-window collapse preferences survive responsive mode changes. Compact and minimal modes open the pane as an overlay and close it after navigation.
- A 28–32 DIP content inset, 8 DIP artwork corners, restrained native control surfaces, and the system accent for primary actions and progress.
- Home uses a 156 × 234 DIP poster, 272 × 153 DIP landscape card, and quiet 220 × 64 DIP library tile with an icon and name. Poster-wall columns share the available width while retaining the 2:3 artwork ratio.
- Detail text, artwork, episodes, cast, and media information share a continuous vertical scroll surface. Movie artwork uses a 160 × 240 DIP poster, becoming 112 × 168 DIP above the text in narrow layouts. Episodes use 16:9 artwork. Layout thresholds account for text scaling. The overview initially shows four lines, with Read more only when text is trimmed.
- One non-interactive window backdrop sits below the title bar and content rows. Theme-aware horizontal and vertical masks provide text contrast; cards, badges, dividers, secondary controls, and episode rows use shared translucent resources. High contrast removes the image and uses system colors. Disabling advanced effects makes surfaces solid while retaining ordinary imagery; system animation settings govern the optional 220ms arrival fade.
- Home and detail shelves use native horizontal scrollbars, touch and touchpad gestures, and keyboard navigation. Custom left/right buttons do not duplicate the scrollbars. See all is a separate navigation action, not a scroll control.
- Initial loading uses a 32 DIP ProgressRing within the content area and a short status label. Background refresh, sorting, and filtering retain the header, toolbar, scroll container, and current results while a two-DIP progress indicator overlays the content edge. Loading another page and loading a season have local progress states. Routine loading does not insert an InfoBar or a banner.
- Search submits from its page on Enter or the search icon; Ctrl+F opens that destination and focuses the input. Draft text does not submit a query. Watch status is a labeled single-choice selector, rather than an isolated toggle. Next up and Continue watching keep their endpoint-defined ordering and omit unsupported sort and watch-status controls.
- Horizontal shelves have a finite viewport height calculated from Windows text scaling. Their text rows remain auto-sized; the finite viewport preserves virtualization inside the vertical page scroller.
- Cast and crew includes the available people in a responsive horizontal row. View all changes a larger cast to a bounded grid; Show less returns to the row. Selecting a person opens an independent browsing destination rather than a modal dialog.
- Media information has responsive Video, Audio, and Subtitles cards beneath cast. Source selection, additional-track disclosure, and each track's Technical details disclosure retain state by media/source/track identity. Only actual server fields appear; missing groups are omitted.
- Player transport uses a 48 DIP central play/pause control. Volume, subtitle, queue, settings, and fullscreen remain available at narrow widths; maximum bitrate also remains in settings when its shortcut is hidden. Independent queue/settings content uses a 360 DIP side area at player widths of at least 1040 DIP and overlays the video below that width. Each panel retains its scroll and focus context. Windowed playback uses the native title bar; the internal header and More menu appear in fullscreen. Controls hide after three seconds only during active playback and when pointer, keyboard focus, open panels, errors, and timeline interactions allow it. Reserve space for controls keeps fullscreen controls below the picture.
- Previous episode and Next episode use resolved server episode order and leave manually queued entries intact. Movie playback omits them. The queue separates Now playing, Queued by you, and optional next-episode context; Play next in queue starts the queue head, regardless of selection.
- Recoverable playback failures remain visible across queue and diagnostics navigation. Change settings creates a retry draft; Apply and retry preserves recovery identity, position, and pause state, while Cancel or closing the panel discards the draft. Maximum bitrate choices respect the effective account cap.
- Diagnostics lead with status and recent events. Copy snapshot uses safe JSON; Save as opens the native save picker with a timestamped JSON filename. Canceling that picker exports nothing, and the dialog reports operation results inline.
- Connection progress is a local 20 DIP ring with a cancel action. Confirmations for sign-out and account removal default to Cancel and explain the specific account effect.

## Data and lifetime

Home requests at most 16 items per shelf with at most three concurrent metadata requests. Useful Home and episode content can appear before optional data completes. Partial Home refreshes commit successful shelves while retaining prior data for failed shelves; Continue watching and Next up are deduplicated by identity and state. Navigating, searching, switching accounts, and changing seasons invalidate obsolete responses.

Background refresh stages metadata before committing it. It reloads the already-fetched page range, updates matching media objects in place, and retains the existing content if the refresh fails. Page, session, and season ownership checks reject obsolete results, while later successful favorite or watched-state changes are preserved. History retains loaded windows, location/filter/sort state, and scroll/focus anchors. Ordinary refresh does not reset the collection revision or viewport. A failed filter change restores the committed selection; an empty filtered collection offers Clear watch filter. Loading, failure, cancellation, and genuine empty results remain distinct, including after dismissing an error notice. Season switching exposes local progress and cancellation while preventing actions from targeting stale episode content.

Artwork selection distinguishes Poster, Landscape, and Backdrop. Landscape cards prefer appropriate episode artwork, thumbnails, or backdrops; a detail backdrop does not fall back to a portrait poster. Existing authenticated cache isolation, four-download concurrency, bounded byte storage, container realization ownership, cancellation, and old-result rejection are retained. Resetting a collection retires its images without clearing unrelated library tiles or the detail hero.

The main poster wall keeps a bounded viewport and virtualized GridView. Home and card-view detail shelves use bounded horizontal viewports; the episode list uses a bounded vertical viewport. Incremental loading appends the next page without moving the existing content. Person works load in pages of 24 through the real Emby PersonIds filter and use the account-scoped image cache. The person view model remains in browsing history when a work opens; removing that history or ending the session cancels its lifetime. No fabricated cast data or complete-library preload is introduced.

The window backdrop uses the authenticated cache with a fixed 1600 × 1000 request and aspect-preserving decode. Session and request identity checks reject stale image results. Theme and system-preference subscriptions are cleaned up with the view. Shared mutable brushes keep existing resource references current.

Account connection recovery distinguishes credential failures, network failures, host identity changes, and policy restrictions. Cancellation applies while a connection is unfinished; cancellation arriving after a successful service commit does not discard the committed session. Sign-out tracks unfinished local-token and server-revocation work separately. `EMBY_CLIENT_DATA_ROOT` supports isolated verification with a process-scoped data directory; explicit constructor paths still take precedence, and normal default paths are unchanged when the variable is absent.

## Interaction guidance

[Windows scrolling guidance](https://learn.microsoft.com/en-us/windows/apps/design/controls/scroll-controls) recommends built-in collection scrolling and documents the input-aware native scrollbar. The [panning guidelines](https://learn.microsoft.com/en-us/windows/apps/design/input/guidelines-for-panning) recommend hiding scroll indicators when custom navigation replaces them. This interface instead keeps native scrollbars as its single shelf-scrolling control and separates navigation to the full collection.

[Windows progress guidance](https://learn.microsoft.com/en-us/windows/apps/design/controls/progress-controls) distinguishes progress rings from progress bars. Initial empty content uses a ring, and the content-edge bar indicates background work without changing the surrounding layout. [RadioMenuFlyoutItem](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.controls.radiomenuflyoutitem) provides native mutually exclusive choices for the appearance menu.

[NavigationView](https://learn.microsoft.com/en-us/windows/apps/design/controls/navigationview) supplies adaptive navigation, while this implementation keeps the search input on its dedicated destination so it remains usable with a collapsed pane. The native TitleBar owns the window-level navigation controls. [ComboBox](https://learn.microsoft.com/en-us/windows/apps/design/controls/combo-box) provides the compact single-choice control used for watch status. These are project-specific choices; WinUI does not prohibit a ToggleButton for other clearly labeled two-state actions.

In the 2026-09-10 source, the play-queue activation failure was reproduced natively: the string `Icon="Down"` cannot convert to a valid Symbol. Explicit FontIcon arrows replaced the shorthand conversion. Empty, populated, reordered, removed, cleared, and reopened queue paths passed the isolated native dialog probe recorded in [queue verification](verification/queue-dialog-native-20260910.json). That receipt retains its historical source identity.
