# UI and UX review: 2026-09-15

## Decision

Keep the current WinUI foundation. Native navigation, title-bar integration, quiet content loading, real media metadata, safe account confirmations, and the centered player transport are appropriate. The application can become more modern within Fluent Design by improving information hierarchy, content density, and consistency. A replacement visual system or another decorative banner is not justified.

The next revision should separate **behavior corrections** from **visual refinement**. Several confusing states are established in source, and four were corroborated in the native application during this review. Address those before treating additional blur, spacing, or color changes as the main improvement. No production changes are proposed as completed by this report.

All current pages and relevant auxiliary surfaces have a conclusion below. A conclusion can be source-based without claiming full native acceptance. There is no invented numerical design score and no finding established at P0 or P1. P2 denotes a material workflow or information issue; P3 denotes smaller consistency or polish work. Priorities describe impact, while evidence labels describe confidence.

### Pagination timing: source-confirmed, not native-reproduced

The reviewer attempted delayed next-page refresh with 5-second and 20-second delays, but both actions missed the required in-flight cancellation window. A third Ctrl+R attempt was blocked by the tool's user-input guard. The capture named `12-cancel-pagination-with-refresh.png` therefore **does not establish successful cancellation or the stall**, just as `08-refresh-during-pagination.png` establishes the visible item range rather than the race. The source execution path still supports B3 at P2; occurrence and native recovery need a controlled follow-up. A suggestive artifact filename is not an observation.

## Design opportunities, distinct from defects

1. **Home should serve viewing intent sooner.** Move useful Continue watching content up, compress redundant library navigation, reduce unused shelf reservations, and define deliberate cross-shelf deduplication. Preserve useful two-line titles, stable poster sizes, and access to distinct episodes.
2. **Details need a more deliberate content-to-space balance.** Limit overview width, adapt the cast preview to one complete row, and size short episode sections to their content. Multiple vertical viewports are an interaction cost to evaluate, not a blanket Fluent violation. Preserve virtualization when choosing a clearer scroll model.
3. **Parent and exploration context should be easier to keep.** Add series context on episode/season pages, distinguish history from source-library navigation, and retain person-works position when comparing works. Back already returns from a person's selected work to the original media; the cost is the lost person context, not a completely broken chain.
4. **Initial useful content can arrive sooner.** Home currently waits for all independent shelves, and series initialization waits for optional resume/next-up alongside episodes. B7 and D4 are conditional response-time opportunities; they are not measured data errors. Preserve atomic background refresh while considering progressive initial results.
5. **The player needs a coherent viewing surface and clearer priorities.** Keep the stable transport and native interaction model. Coordinate the local video/dock tones, strengthen ten-second seek readability, group settings, and reduce the prominence of low-frequency bitrate/empty-queue information. Real bright and dark media must guide the final visual decision.
6. **Queue language should describe two different concepts accurately.** Explicit queue entries and automatically discovered next episodes are different. The manual buttons are labeled Next in queue and correctly gate on explicit entries; natural episode continuation has historical native evidence. Broad “0 upcoming items” wording makes that distinction harder to discover. This is a semantics/product decision, not proof of broken advance logic.
7. **Account and diagnostic surfaces need selective simplification.** Remove unnecessary first-run disclosure, keep errors near the relevant form, make account identity readable, and make diagnostic exports easy to retrieve. Native controls and safe confirmation defaults can remain.

These refinements align with Fluent through consistent hierarchy, semantic surfaces, readable type, intentional spacing, and familiar Windows behavior. More blur, larger corner radii, or a custom card around every section would not by themselves improve the experience. Microsoft guidance supports [typographic hierarchy](https://learn.microsoft.com/en-us/windows/apps/design/style/typography), [semantic Mica surfaces](https://learn.microsoft.com/en-us/windows/apps/design/style/mica), [layering](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/layering), and [native dialogs](https://learn.microsoft.com/en-us/windows/apps/design/controls/dialogs-and-flyouts/dialogs). None of these references mandates a particular Home order or one universal cast count.

## Native validation gaps

The review has conclusions for all surfaces; it does not erase the following acceptance boundaries:

- **Accessibility and adaptation:** high contrast, 200% Windows text size, Narrator, minimum-height dialogs/panels, long international metadata, and runtime theme changes. See Microsoft's [text accessibility guidance](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessible-text-requirements) and [contrast-theme guidance](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/high-contrast-themes).
- **Focus and interaction:** narrow overlaid Settings/Queue Tab traversal, delayed search ownership, failed-authentication/cancellation focus, realized-card UIA names after updates, long-queue reordering/removal, and return anchors across all collection types.
- **Real media:** photographic bright/dark backdrops, landscape episode frames, multiple sources/audio tracks, real selectable subtitles, long stream names, and reserved-control-space subtitle behavior. The synthetic color sample proves playback structure, not final art direction.
- **Recovery and latency:** initial saved-token rejection/decryption failure, inaccessible/corrupt settings, partial sign-out persistence/revocation failure, actual player failure/retry/diagnostic entry, pagination cancellation timing, pending season transitions, and independent biography/works failures.
- **Less-observed pages:** direct season and episode detail, a fully expanded cast, a long person-works session, full Continue watching/Next up collections, successful empty searches/filters, no-library accounts, and the actual populated player queue side panel.

## Recommended decision boundary

The review identifies a potential **behavior correction scope**: truthful load/error states, history anchors, bitrate selection, F11 consistency, cancellation-aware pagination, account recovery, and complete media/queue identity. Preserve working playback ownership, stable refresh commits, server ordering, local account semantics, and native controls.

Review a separate **visual refinement scope** against representative content: Home density, detail reading width and reflow, cast/episode section sizing, aligned search headers, a coherent player surface, and grouped settings/diagnostics. Decide person-works navigation and automatic-next queue presentation explicitly because they alter interaction structure.

Do not bundle background playback while browsing, a mini-player, localization, or new recommendation features into cosmetic modernization. Those are independent product choices. This turn ends with a review and decision basis; it does not implement or implicitly approve the next revision.
